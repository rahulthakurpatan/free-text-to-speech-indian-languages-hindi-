Gemini TTS Prompt Examples: Natural Voice, Pacing & Emotion

Practical, editable prompt patterns for teachers, storytellers, YouTube creators and voiceover producers—with API-specific caveats.

17 November 2026·Vāṇī AI Editorial·Practical prompt guide
PROMPT · LISTEN · REFINE

Quick answer

For more natural AI narration, specify the audience, speaking tone and pace; provide clean punctuation; select a compatible voice; then test a short script. In current Gemini 3.8 Interactions API examples, style guidance can live in speech metadata. Older Gemini TTS workflows use different prompting and configuration patterns.

Key takeaways

  • Describe a specific delivery rather than demanding “perfect human” speech.
  • Keep the transcript clear and test one change at a time.
  • Use supported style metadata for the model and endpoint in use.
  • Review pronunciation and language support before publishing.
  • Listen to the generated audio: prompt instructions are not guarantees.

What makes a useful Gemini TTS prompt?

A useful voice prompt describes the desired delivery rather than asking the model to “sound human.” Give the listener context, a consistent speaking style, a sensible pace and an exact transcript. The best result still depends on the chosen voice and model. Test with a short sample before generating a long project.

Google's current TTS documentation distinguishes newer Interactions API speech metadata from older prompt-as-text patterns. For Gemini 3.8 TTS, sustained delivery direction can be provided with speech_metadata annotations. Do not paste unsupported JSON fields into a different API and expect them to work.

Six practical prompts for creators

These are original writing templates, not claims that every model obeys each instruction perfectly. Use the spoken text as the transcript and adapt the delivery instructions to the interface you use.

1. Clear educational lesson

Delivery: Calm, patient teacher. Moderate pace. Make definitions easy to follow.
Transcript: A solar panel converts sunlight into electricity. Let's explore how.

Use for tutorials, exam preparation and e-learning. Test technical terms and numerals aloud.

2. Friendly YouTube introduction

Delivery: Warm, upbeat host. Conversational but not exaggerated.
Transcript: Welcome back! Today we're comparing three simple ways to learn a new language.

Use natural pauses instead of overloading the text with exclamation marks.

3. Bedtime story

Delivery: Gentle storyteller, soft and unhurried. Slight wonder, no sudden shouting.
Transcript: The little lantern glowed beside the window. Outside, the rain had finally stopped.

Choose a voice that naturally suits the tone; forcing an extreme character can sound inconsistent.

4. Product explainer

Delivery: Clear, confident, neutral. Emphasize benefits without sounding like a hard sell.
Transcript: Track your monthly spending in one place. Review the numbers before making a decision.

Avoid unverifiable marketing promises and test brand-name pronunciation.

5. Documentary narration

Delivery: Reflective, measured narrator. Slightly slower pace, subtle emphasis.
Transcript: In the early morning, the village market opened beside the river.

Use factual scripts and distinguish dramatic narration from unsupported historical claims.

6. Short-form video hook

Delivery: Energetic and concise, with a brief pause after the opening question.
Transcript: Why do some recordings sound robotic? The answer often begins with the script.

Keep the hook understandable without exaggerated shouting.

Where to put style instructions in Gemini 3.8

For the documented Gemini 3.8 Interactions API, Google's examples attach a speech_metadata annotation to a text part. A minimal conceptual illustration is:

{
  "type": "text",
  "text": "Welcome to today's lesson.",
  "annotations": [{
    "type": "speech_metadata",
    "style": "calm and encouraging, moderate pace"
  }]
}

This is an excerpt of a request part, not a complete API request. You must still select a supported model, configure audio output and a voice, authenticate, and follow the current API reference. Older Generate Content examples use different field names and response locations. See Google's current speech-generation guide for complete examples.

Punctuation and pauses: what actually helps

Start with ordinary punctuation. A period signals the end of a thought; a comma creates a light syntactic break; a new paragraph often gives the listener a more meaningful reset. Ellipses can suggest hesitation, but too many can produce unnatural timing.

Less clearMore natural script
Welcome everyone today we beginWelcome, everyone. Today, we begin.
It costs 2500 rupeesIt costs two thousand five hundred rupees.
Our next step is testing then publishingOur next step is testing. Then, we publish.

Google's prompting guide also documents model-specific inline pause tags. Only use those when your selected model and endpoint support them; otherwise they may be read aloud or ignored.

Better pronunciation for Hindi and regional-language scripts

Write the actual words in the intended script when possible, especially for names and regional terms. Avoid mixing Roman transliteration and native script without testing. For example, a Hindi lesson can use नमस्कार! आज हम एक नई कहानी सुनेंगे। rather than a phonetic approximation that may be interpreted differently.

Expand uncommon abbreviations and write numbers in spoken form when their reading matters. Test place names, borrowed English terms and honorifics. Pronunciation depends on language and voice support, so review the model's documented language coverage rather than assuming every voice supports every accent.

Two-speaker conversations and podcasts

Multi-speaker synthesis is not simply “add two character names” in every API. Google's current Gemini 3.8 Interactions API example uses conversational mode with a speakers configuration and speaker metadata on each turn. The legacy Generate Content workflow uses a different multi-speaker configuration. Match the sample to your exact endpoint.

For a script, keep speaker turns distinct: Host: “What should beginners check first?” Guest: “Start with a short sample and verify every sentence.” Use two clearly differentiated voice choices, and check turn-taking and timing after generation.

For interviews, do not fabricate a real person's voice or imply they spoke words they never said. Label fictional or synthetic conversations where the context requires it.

A repeatable A/B listening test

  1. Choose a 15–30-second transcript with one name, one number and one sentence needing emphasis.
  2. Generate version A with a simple neutral delivery.
  3. Generate version B with one changed instruction, such as “slightly slower pace.”
  4. Listen at normal speed and compare intelligibility, pronunciation, pauses, volume and unwanted artifacts.
  5. Keep the stronger result and note the exact voice, model and settings.

Change one variable at a time. If you change voice, pace, transcript and model together, you cannot tell which change improved the result.

Frequently asked questions

How do I make Gemini TTS sound less robotic?

Use natural punctuation, select a suitable voice, provide specific pace/tone guidance and review a short test. No prompt can guarantee natural speech on every output.

Can Gemini TTS control emotion?

Supported models allow style guidance, including tone and pace. Exact controls depend on the model and API workflow; follow current official examples.

Can I make a two-person podcast?

Supported Gemini TTS workflows offer multi-speaker configuration. Use the correct speaker configuration for your selected model and endpoint, and verify the generated dialogue.
