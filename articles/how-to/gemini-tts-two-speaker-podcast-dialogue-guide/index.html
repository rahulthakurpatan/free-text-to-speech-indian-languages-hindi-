Gemini TTS Two-Speaker Podcast: Dialogue & Voice Switching

Quick answer

To make a two-person podcast with Gemini TTS, prepare short alternating turns, map each speaker name to a specific voice in the supported multi-speaker configuration, render a short sample, and listen for swapped voices or missing dialogue. The exact request format depends on whether you use the newer Interactions API, legacy Generate Content API or Google Cloud Text-to-Speech. A plain script pasted into a single-speaker text box does not automatically turn that box into a two-voice generator.

Why the speaker labels alone are not enough

A script that says “Host: Hello” and “Guest: Hi” is a transcript, not necessarily a voice-routing instruction. The synthesis endpoint must know which two speaker identifiers are valid and which voice belongs to each. Creators have reported cases where Google AI Studio reads both roles in one voice after interface changes. Treat that as a workflow mismatch to diagnose, not proof that all Gemini TTS endpoints have removed multi-speaker support.

Google's current documentation describes two-speaker synthesis, while a developer forum thread documents voice-assignment inconsistencies. Neither source guarantees a perfect result on every request.

Step 1: Write a short two-host test script

Start with 4–6 turns rather than a full 15-minute episode. Use exactly the same speaker identifiers throughout. Keep stage directions outside the words intended to be spoken, or use a supported style field where the chosen API provides one.

Host: Welcome to our Hindi learning podcast.
Guest: Thanks! Today we will practise everyday greetings.
Host: How do you say good morning in Hindi?
Guest: You can say, “सुप्रभात”.
Host: Great. Let's say it slowly once more.
Guest: सुप्रभात.

For a Hindi lesson, keep intended Hindi words in Devanagari and test names separately. Mixing scripts can change pronunciation; there is no universal phonetic spelling that works across every voice.

Step 2: Choose the right Gemini API format

Legacy Generate Content TTS: Google's official speech-generation guide shows multiSpeakerVoiceConfig with two speakerVoiceConfigs. The speaker identifiers in the prompt must match the configuration. A simplified illustrative configuration is:

{
  "multiSpeakerVoiceConfig": {
    "speakerVoiceConfigs": [
      {"speaker": "Host", "voiceConfig": {"prebuiltVoiceConfig": {"voiceName": "Kore"}}},
      {"speaker": "Guest", "voiceConfig": {"prebuiltVoiceConfig": {"voiceName": "Puck"}}}
    ]
  }
}

This fragment is not a complete API request. It belongs inside the appropriate speech configuration with a compatible model, audio response settings and authentication. Copy the complete working example from Google's documentation for your endpoint instead of mixing fragments from different API generations.

Interactions API: newer documentation uses turn-level speaker metadata and a speech_config containing two speaker definitions. Do not paste a legacy multiSpeakerVoiceConfig object into an Interactions API call. Verify the exact SDK version and model-specific schema in the current Gemini speech documentation.

Cloud Text-to-Speech: Google Cloud additionally documents structured turn-based multi-speaker markup, with its own constraints and authentication. These are separate products/interfaces, not interchangeable payloads.

Step 3: Render, inspect and correct

  1. Confirm endpoint and model. Check that the selected model and endpoint explicitly support two speakers.
  2. Lock names and voices. Use stable names such as Host and Guest and map each to a fixed voice ID.
  3. Generate the first six turns. Avoid debugging a whole episode before the basic routing works.
  4. Check the transcript against audio. Mark every omitted, duplicated, or invented word and each voice swap.
  5. Retry a short section. If a line fails, regenerate that segment and compare it with the original rather than assuming retry always fixes it.
  6. Expand by scene. Keep voice mapping and pronunciation notes identical across segments; review joins before export.

For longer narration, use the separate long-text chunking workflow. The workflow reduces the cost of finding errors, but cannot promise identical timbre across independent generations.

Can I do this inside Vāṇī Studio 2.0?

Vāṇī's current Hindi Studio is a convenient BYOK single-voice narration workflow. This guide does not claim that its existing editor exposes a two-speaker configuration. You can use it to audition short individual lines and compare voices, while a dedicated multi-speaker API integration is required for the structured two-speaker examples above. Do not assume a single text area automatically switches voices.

Pre-publication checklist for dialogue creators

  • Read the script alongside the generated audio and confirm every turn is present.
  • Listen for accidental voice swaps, especially after long pauses or scene changes.
  • Verify difficult names and Hindi words by ear; transcription alone can hide mispronunciation.
  • Keep speaker/voice IDs, model version and prompt notes in your production log.
  • Ensure you have rights to the script, music and any third-party material you add.
  • Check the destination platform's synthetic-media and disclosure policies where relevant.

Frequently asked questions

Does Gemini TTS support two speakers?

Yes, supported Gemini TTS API routes document two-speaker synthesis. Availability and request structure depend on the model and endpoint you use.

Can I paste a whole script into one text box?

Only if that particular interface is designed to parse and map dialogue. A generic single-speaker editor may simply read every line with one voice.

Why does my podcast change voices mid-sentence?

Voice routing or generation can be inconsistent. Verify speaker IDs, simplify the prompt, shorten the section and review the rendered audio. There is no universal guaranteed fix.

Can I use Hindi and English in one dialogue?

You can test multilingual dialogue with supported models, but listen closely to pronunciation, especially names, mixed scripts and code-switched sentences.
