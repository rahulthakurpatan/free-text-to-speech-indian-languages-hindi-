Gemini 3.1 Flash TTS Shutdown: Migrate to Gemini 3.8

The November 17, 2026 model shutdown is a concrete reason to check your TTS model ID, request structure and audio handling—before blaming your API key.

18 November 2026·Vāṇī AI Editorial·Official documentation reviewed

Quick answer

Google's Firebase AI Logic TTS documentation says gemini-3.1-flash-tts-preview shut down on November 17, 2026. The documented replacement models are gemini-3.8-flash-tts and gemini-3.8-flash-lite-tts. Updating the model ID is the first step, but migration also requires checking how your application sends speaking instructions and decodes audio. These details are API- and SDK-specific; do not blindly copy a Firebase sample into another endpoint.

Key takeaways

  • Check your exact model string before troubleshooting a newly failing voice generator.
  • Choose 3.8 Flash for expressive, studio-style output; consider 3.8 Flash Lite for throughput and latency needs.
  • Review the newer structured SpeechMetadata approach instead of assuming older prompt-only styling behaves identically.
  • Check whether your API returns a complete WAV file or headerless PCM stream; wrong decoding can sound like silence or noise.
  • Test a short Hindi/English script before attempting long narration.

What changed on November 17, 2026?

Google's Firebase AI Logic TTS documentation explicitly names the gemini-3.1-flash-tts-preview shutdown date and provides a migration section. If an application still targets that exact retired model, changing its API key or browser cache alone is not a complete fix. First inspect the model string used by the actual request. Model availability and behavior may differ between Gemini Developer API, Firebase AI Logic and Cloud Text-to-Speech; consult the documentation for your chosen provider.

Vāṇī AI note: the current Vāṇī Studio engine source was inspected on November 18 and references gemini-3.8-flash-tts, not the retired 3.1 preview model. This article is a migration reference for developers and creators using older integrations, not a claim that the current Vāṇī Studio is broken.

Migration checklist: change the model safely

  1. Locate the model ID. Search the deployed code and configuration for gemini-3.1-flash-tts-preview. Confirm which endpoint sends the request.
  2. Read the correct provider's migration guide. Firebase AI Logic, Gemini Developer API and Cloud TTS have different client libraries and examples.
  3. Choose a supported replacement. For Firebase AI Logic, Google's documented choices include gemini-3.8-flash-tts and gemini-3.8-flash-lite-tts.
  4. Review speaking instructions. The new generation emphasizes structured speech metadata and inline vocal tags. Older free-form instructions may need adaptation; preserve the exact words that should be spoken.
  5. Keep the voice configuration valid. Select a supported voice, and provide a BCP-47 language code where appropriate; do not assume a voice from a different API will work unchanged.
  6. Check audio decoding. Inspect the actual response MIME type and whether it includes a WAV header.
  7. Run a short regression suite. Check spoken text, duration, Hindi names, numerals, pauses, errors and the exported file.
  8. Deploy with rollback. Retain a known-good version and log response metadata without exposing API keys or user text.

For a separate troubleshooting path when audio is missing even on a supported model, see Gemini TTS not working: API and audio fixes.

WAV versus PCM: avoid the silent-audio trap

In the Firebase AI Logic documentation, a normal generateContent request returns audio/wav by default: 16-bit linear PCM, 24 kHz, mono, inside a standard WAV container. Streaming generateContentStream returns audio/l16: raw PCM chunks without a WAV header. Do not prepend another WAV header to an already complete WAV file, and do not hand headerless PCM bytes to a decoder that expects a RIFF WAV container.

Before converting to MP3, inspect the response MIME type, sample rate, channel count and byte length. An HTTP success response alone does not prove that an audio player received a valid playable file. These specific defaults are documented for Firebase AI Logic; other endpoints can differ.

A practical 5-minute Hindi and English voice QA plan

Use the same short script for both candidate models and listen with headphones. A sample for human review (not a claim of automated test success):

नमस्कार! आज 18 नवंबर 2026 है। Your order number is A-104. कुल राशि एक हज़ार पाँच सौ रुपये है। अगला अध्याय शुरू करते हैं।

Check whether the model preserves both languages, handles the date and order number appropriately, maintains the intended voice, and exports a playable file. Repeat with a second script containing a proper noun and a deliberate pause. For a longer script, use a chapter-based QA workflow rather than assuming a fixed safe length; see long-text Gemini TTS chunking and natural-voice prompting. These are suggested checks, not independently measured Vāṇī performance results.

Frequently asked questions

Is gemini-3.1-flash-tts-preview still supported?

Google's Firebase AI Logic documentation states that the model shut down on November 17, 2026. Check the latest official provider documentation for availability in your environment.

Will changing only the model name fix every TTS error?

No. Validate the provider, request schema, voice configuration, response MIME type and audio playback path as well.

Which new model is best for Hindi voiceovers?

For expressive narration, start by evaluating Gemini 3.8 Flash TTS. For throughput-focused use, compare Flash Lite. Always audition your real Hindi script; no model is guaranteed to pronounce every name perfectly.

Does Vāṇī AI require users to supply their own API key?

Vāṇī Studio follows a bring-your-own-key workflow. Follow the site's Gemini API key guide and never publish or share your key in a script, screenshot or support post.
