Gemini TTS Not Working? Fix No Audio & API Errors

A practical 2026 troubleshooting guide for empty audio responses, wrong model endpoints, quota failures, and WAV-versus-PCM playback mistakes.

Updated: 16 November 2026·By Vāṇī AI Editorial·12-minute troubleshooting guide
AUDIO · API · FIXES

Quick answer: why is Gemini TTS returning no audio?

First identify whether your request failed with an HTTP error, succeeded but returned no audio bytes, or returned bytes your player cannot decode. Check the exact model ID and API workflow, inspect the response's audio field, retry one short supported-language sentence, and match the returned audio format to your playback code. Do not assume HTTP 200 means a playable file exists.

What to check first

  • Using Gemini 3.8 TTS? Current Interactions API examples return audio in interaction.output_audio.data, not the older candidates[].content.parts[].inlineData.data location.
  • Wrong file format? Gemini 3.8 unary audio defaults to complete WAV; older TTS workflows may have expected headerless PCM.
  • Empty result? An HTTP 200 response can still contain no usable audio. Inspect finish reasons and payload fields, then retry conservatively.
  • Quota or access error? Resolve key restrictions and model availability before repeating the request.

1. Start with the actual symptom—not a random fix

The words “Gemini voice not working” cover several different failures. A server error is not the same as a silent audio file, and neither is the same as a response that contains no audio field. Treating them separately saves time and avoids repeated paid requests.

Google documents API status codes and generation-blocked reasons separately; a safety- or language-blocked response should not be treated like a recoverable network outage.

2. Test the smallest possible TTS request

Before debugging an entire audiobook script, use a short sentence like “Hello! Welcome to today's lesson.” Disable extra prompt decorations and complex multi-speaker configuration. A successful short test helps isolate script length, voice setup, or formatting problems.

For the current Gemini 3.8 TTS workflow

Google's documented Interactions API example uses model gemini-3.8-flash-tts and an audio response format. The resulting bytes are available as interaction.output_audio.data. The following example is an illustrative payload structure; authenticate with your own key using Google's supported method.

POST /v1beta/interactions
{
  "model": "gemini-3.8-flash-tts",
  "input": [{
    "type": "user_input",
    "content": [{
      "type": "text",
      "text": "Hello! Welcome to today's lesson."
    }]
  }],
  "response_format": { "type": "audio" },
  "generation_config": {
    "speech_config": [{ "voice": "Kore" }]
  }
}

Check the result: Confirm that output_audio.data exists and is non-empty before decoding it. A complete unary WAV result should usually begin with a RIFF/WAVE file signature after Base64 decoding. Do not log or share a live API key when requesting help.

Using an older generateContent request instead? Its candidates[].content.parts[].inlineData response shape is a different workflow. Always follow the docs for your specific model and API method; mixing old and new examples is a common source of false “no audio” errors.

3. Fix HTTP 200 but no audio returned

HTTP 200 confirms that the server handled the request, not that the requested audio was generated. A May 2026 community report documented an older Gemini TTS preview returning HTTP 200 with usage metadata, finishReason: "OTHER", and an empty content object. Later retries sometimes worked. This is a reported symptom, not proof of one universal cause.

Example: older preview response with no audio
{
  "candidates": [{
    "content": {},
    "finishReason": "OTHER"
  }],
  "usageMetadata": { "totalTokenCount": 6229 }
}

There is no playable inlineData.data field. Your application should show a meaningful failure message rather than manufacturing an empty file.

  1. Save the HTTP status, model ID, sanitized response shape, finishReason (if supplied), and whether the audio field is empty. Never store API keys or private scripts in public logs.
  2. Run the same request with a short plain sentence and a supported prebuilt voice.
  3. Retry only transient conditions with a small capped retry count and backoff; repeated calls may consume quota or incur charges.
  4. Check the model deprecations list and migrate from a legacy preview model when needed.
  5. If the failure persists, inspect Google's developer forum and report a reproducible sanitized example with the model, endpoint and status code.

For policy-blocked content, change the underlying input appropriately instead of endlessly retrying. For stable, repeatable empty responses, investigate the request and output parsing first.

4. Gemini 3.8 WAV versus raw PCM: why audio may sound broken

This is an important migration detail. Google's current Gemini 3.8 TTS documentation describes a complete WAV file for a normal unary response (audio/wav, typically mono 24 kHz 16-bit PCM). Streaming responses default to headerless raw PCM (audio/l16), and older TTS examples often manually built a WAV header around raw PCM.

Audio responseExpected handlingWhat not to do
3.8 unary WAVBase64-decode and save/play the WAV bytes directlyDo not prepend another RIFF header
3.8 streaming raw PCMAssemble audio chunks, then decode using declared sample rate, channels and sample widthDo not rename raw bytes .wav without a valid container
Explicit audio/l16Interpret as raw signed 16-bit PCM at the configured sample rateDo not assume the bytes already contain WAV metadata
MP3 reminder: A browser tool may offer an MP3 download after converting audio. That does not mean Gemini 3.8's default API output is MP3. Check the generated MIME type, then convert only if your app requires that format.

What to inspect in the decoded bytes

A WAV file normally starts with RIFF and later includes WAVE. If you see that header, do not wrap it in a second WAV container. If your response is explicitly audio/l16, the bytes will not have a WAV header; configure your decoder or package the PCM bytes correctly.

5. Gemini TTS API errors: what each category means

400: Invalid argument or request shape

Confirm your chosen model accepts audio generation, your JSON fields match its API method, and your speaker/voice configuration is valid. The Gemini 3.8 Interactions example is not a drop-in replacement for older generateContent payloads.

401 / 403: API key or access is rejected

Verify the current key in Google AI Studio, its restrictions, the associated project, and access to the requested model. Google's 2026 key guidance describes a transition toward authorization keys. Recreate a restricted key if your key is blocked or obsolete, rather than removing security controls.

404: Wrong model ID or API endpoint

Check the exact model string against Google's model catalog. Do not accidentally substitute a Live model, a transcription model, or a discontinued preview ID for a TTS model.

429: Rate or quota exceeded

Stop rapid retries. Use exponential backoff, review project usage and billing tier, and reduce concurrent generation jobs. Being able to open AI Studio does not guarantee your project has available API quota at that moment.

500 / 503 / 504: Server failure or timeout

These can be temporary. Retry conservatively, consider shortening a very long script, and distinguish a true server failure from a client-side timeout. If repeated failures affect multiple short requests, preserve a sanitized response and check service updates.

Blocked generation: safety or unsupported language

Google also documents generation-blocked reasons such as safety, language, and prohibited content. Those are not fixed by network retries. Review the response and adjust the input or language choice where appropriate.

6. Check your Gemini API key without exposing it

Vāṇī Studio 2.0 works on a bring-your-own-key basis: you supply a Gemini API key for your own Google project. Google manages API quotas, permissions, and any applicable charges. A key is not a promise of unlimited free use.

  1. Open Google AI Studio's API key page and inspect your current key's status and type.
  2. Confirm the key is permitted for the Gemini API and linked to the intended project.
  3. Review current quota and usage. For a chargeable project, check billing settings before large tests.
  4. Test using a short non-sensitive script.
  5. Revoke any key you suspect was leaked. Never paste an API key into a bug report, article comment, or GitHub issue.
Security: Google's guidance recommends backend key handling for production apps. Any key deliberately entered into a browser-based BYOK tool is accessible within that browser context; use a dedicated, restricted key and understand the local-storage and third-party-script implications before choosing to save it.

7. Fix unusual pronunciation, accents or incomplete narration

If audio is generated but the voice sounds wrong, the issue may be linguistic rather than technical. Start with correctly encoded Unicode text, proper punctuation and small paragraph breaks. Test challenging names and numbers as separate samples before creating a long narration.

  • Regional-language scripts: Prefer correctly written native Unicode script instead of copied mixed-encoding text. For Hindi, test Devanagari; for Tamil, test Tamil Unicode.
  • Overlong voice direction: Simplify instructions and separate spoken transcript from delivery guidance. Do not ask the model to read production notes aloud.
  • Voice choice: Use a voice and style suited to the script; compare short samples and listen before publishing.
  • Long output: Split scripts into coherent segments when quality drifts or the audio is truncated, then verify transitions manually.

English: “Welcome to our learning studio.”

Test each separately with the target voice and compare its actual pronunciation; sample output may vary by model.

Frequently asked questions

Why does Gemini TTS return HTTP 200 but no audio?

A successful HTTP status can coexist with a missing audio field. Inspect the response payload and finish reason. Some users have reported intermittent empty responses with older preview models. Test a short request and retry conservatively if the issue is transient.

Does Gemini 3.8 TTS output WAV or MP3?

Google documents WAV as the default for unary Gemini 3.8 TTS output, and raw PCM for streaming by default. An MP3 offered by a website may involve additional conversion; do not assume the API sends MP3 automatically.

How can I fix the Gemini API 429 error?

Reduce request frequency, implement bounded exponential backoff, and inspect the project's tier, quotas, and usage. Retrying repeatedly without delay may worsen the problem.

Can I use Gemini 3.1 and Gemini 3.8 code interchangeably?

Not without checking the current docs. Gemini 3.8 examples use the Interactions API and may return audio in a different response structure and format from older preview examples.

Is Vāṇī AI Studio completely free?

The studio supplies a browser interface; Google controls Gemini API quota, terms, and any charges tied to your own key and project. Review your Google account before extensive generation.
